# 实验与验收方案

## 1. 两类验收分别判断

**程序验收**回答：模型账目是否正确、约束是否按定义执行、训练和加载是否能运行、结果是否可复现。

**算法效果验收**回答：在独立数据和一致条件下，DRL 是否降低费用、满足供能要求、具有可接受的期末偏差和运行时间。通过程序验收不能替代算法效果验收。

## 2. 对照方法

| 方法 | 状态 | 用途 |
|---|---|---|
| 随机控制 | 已实现 | 检查环境能否处理无规律动作，不作为高质量性能基准 |
| 规则控制 | 已实现 | 电价驱动 CHP / HP / 电池，验证工程基础行为 |
| PPO | 已实现 | 第一种 DRL 基线 |
| SAC | 已实现 | 第二种 DRL 基线 |
| 完美预知 MILP | 待实现 | 固定模型和未来信息条件下的优化参考 |
| 预测驱动 MPC | 待实现 | 使用决策时可获得预测的滚动优化基准 |

规则控制并未充分利用所有设备，例如默认不调度蓄热和 AC；正式比较应增加经过能源工程师调整的规则。战胜一个简化规则不足以证明先进性。

## 3. 必须输出的指标

| 维度 | 指标 | 解释 |
|---|---|---|
| 经济性 | 日均运行费用、分项费用 | 不把训练惩罚混入实际费用而不说明 |
| 综合训练目标 | 含约束和期末惩罚的日目标 | 与运行费用同时报告 |
| 供能可行性 | 电 / 热 / 冷缺口、不可行小时数、无法处置的电力过剩 | 各载能形式分别查看逐时记录 |
| 储能公平性 | 日末电池与蓄热能量偏差 | 当前软目标可能未完全满足 |
| 新能源 | 弃能量、$1-\sum P^{curt}/\sum P^{re}$ | 可用新能源为零时比例留空；含上网利用，不等于自用率 |
| 排放 | 电网购电与燃气排放 | 使用相同排放因子与核算边界 |
| 约束处理 | 动作修正率、最大能量平衡残差 | 残差为零不能替代缺口为零 |
| 计算 | 总训练时间、环境步数、决策耗时中位数及 P95 | 决策耗时和物理仿真时间分开 |

若基准日费用为正，可计算 $\text{saving}=100(C_{base}-C_{RL})/C_{base}$。基准接近零或为负时不使用这个百分比，直接报告绝对差值。只有在可行性和期末条件可比时才解释为成本节约。

## 4. 推荐实验图表

1. **训练过程**：每种算法多个种子的回合回报，画均值和离散程度；同时查看验证集费用及不可行性。
2. **典型日电热冷平衡**：同一日分别画各设备出力、负荷与缺口。
3. **储能与电价**：电池 / 蓄热 SOC、充放功率、分时电价，检查期末恢复。
4. **算法对比表**：规则、PPO、SAC、后续 MILP/MPC 的费用、违约、末端偏差和耗时。
5. **压力场景**：负荷增加、新能源减少、购电容量降低，检查响应及不可行信息。

`plot.py` 已实现单算法典型日电热冷总平衡、储能、费用和不可行量图，以及可选的训练奖励曲线。逐设备堆叠图、多种子置信区间和跨算法汇总图留给正式实验阶段开发，不要将单次曲线当作统计结果。

## 5. 场景矩阵

| 场景 | 构造方式 | 要检查什么 |
|---|---|---|
| 正常工况 | 原始独立测试日 | 基础费用与供能可行性 |
| 用能高峰 | 测试负荷分别增加 10%、20% | 供能余量、购电与设备出力 |
| 低新能源 | 测试风光可用出力乘 0.7、0.5 | 策略适应和费用变化 |
| 设备参数偏差 | 在隔离测试环境改变效率 / COP | 仿真参数误差影响 |
| 边界能力下降 | 降低购电或锅炉容量 | 是否暴露缺口，后续回退是否有效 |
| 预测误差 | 扩展为“预测观测 / 实际结算”两份输入 | 真实在线信息条件下的可行性 |

前两类数据变换可生成新测试 CSV。对已训练模型做设备故障或参数偏差实验，需要明确增加“测试配置与训练配置不同”的压力测试接口并记录差异；当前标准评估故意读取训练配置，不能直接篡改保存配置规避摘要检查。

## 6. 消融与公平比较

可先研究期末惩罚系数、储能是否启用、历史信息或预测输入的影响。去掉局部限幅的实验只能在隔离仿真中进行，越界动作要如实报告，不能让其获得物理上不存在的功率或能量。

正式比较建议至少 3 个、优选 5 个独立训练随机种子，对每个种子使用完全相同的测试日。训练种子与测试日是不同变异来源：先做同一天配对差值，再报告跨日与跨种子变动，不应把所有相关样本当独立观测夸大统计证据。

PPO 与 SAC 的环境步数可相同，但梯度更新量和算力消耗不同，还需记录训练墙钟时间。验证集决定超参数，测试集只进行冻结后的最终评估。

## 7. 程序验收门槛

以下为当前双精度简化仿真建议门槛，是真实交付时可检查的条件，并非现场控制精度承诺：

| 项目 | 门槛 |
|---|---|
| 手算账目 | 单步功率和费用与手算一致，允许浮点容差 |
| 电热冷残差 | 每时段绝对值小于 $10^{-6}$ kW |
| 储能边界 | 所有已执行状态处于 SOC 范围，容差 $10^{-8}$ |
| CHP 爬坡、购售电能力 | 不超过配置上限，允许浮点容差 |
| 异常输入 | 缺列、NaN、重复 / 缺失小时被明确拒绝 |
| 保存与加载 | 两种算法短训练后可加载，输出全部测试日 |
| 结果证据 | 数据摘要、配置、算法、种子、版本和实际步数齐全 |

算法效果的费用提升目标应由项目负责人依据真实系统与基准确定；此处不预填未经实验的“节约 10%”或“效率提升 50%”。
