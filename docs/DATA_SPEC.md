# 数据接口与真实数据接入

## 1. 输入 CSV

每行一个小时，每个文件由连续完整天组成，首行时间从 00:00 开始。固定时区，不使用会出现夏令时重复或缺失小时的本地时间。单位必须在预处理阶段统一。

| 字段 | 单位 / 类型 | 含义 |
|---|---|---|
| timestamp | 日期时间 | 时段开始时间 |
| electric_load_kw | kW_e | 不含 HP、EC 等模型内转换设备耗电的基础电负荷 |
| heat_load_kw | kW_th | 不含 AC 耗热和 TES 充热的用户热负荷 |
| cooling_load_kw | kW_c | 用户冷负荷 |
| pv_kw | kW_e | 可用光伏出力，未扣除本模型计算的弃光 |
| wind_kw | kW_e | 可用风电出力，未扣除本模型计算的弃风 |
| buy_price_cny_per_kwh | CNY/kWh | 购电价格 |
| sell_price_cny_per_kwh | CNY/kWh | 售电价格 |

```csv
timestamp,electric_load_kw,heat_load_kw,cooling_load_kw,pv_kw,wind_kw,buy_price_cny_per_kwh,sell_price_cny_per_kwh
2025-01-01 00:00:00,100,90,80,20,10,0.65,0.25
```

上面一行仅说明格式，实际加载需要至少一个完整 24 小时日。负荷和新能源出力必须非负；价格可为负，但本版本要求售电价不高于购电价。对负电价市场的特殊运行行为仍需另做验证。

## 2. 校验及预处理责任

`load_days()` 拒绝缺列、非数值、NaN、Inf、重复时间、不连续小时和不足一天的数据。它不会自动插值。真实数据若存在缺失，应由数据工程师制定有记录的填补或剔除规则，并保存原始文件及处理日志。

设备配置包含容量、效率、功率限制和示例排放参数。价格和排放因子需要按实际计费边界核对；示例没有容量电费、需量电费、阶梯气价或设备维护停机。

## 3. 防止信息泄漏

1. 按时间先划分训练、验证和测试区间，再训练预测器或拟合数据归一化参数。
2. 同一天的小时不得随机散落在训练与测试集；高度重叠的滑动窗口同样需要隔离。
3. 未来输入若作为预测特征，必须包含 `issue_time`（发布时刻）和 `target_time`（预测目标时刻），仅允许使用决策时已经发布的预测。
4. 实测负荷及实测新能源用于事后仿真结算；不能把尚未发生的真实值直接作为在线观测。
5. 测试集只用于最终评估；参数调整和选模使用验证集。

当前 `train.py` 检查训练时段早于验证时段，`evaluate.py` 对 RL 检查测试时段晚于验证时段，并核验保存的配置摘要。

## 4. 样例数据的性质

`data/demo` 内文件由 `generate_data.py` 生成，只有简单的日内形状、随机扰动和分时电价，目的是验证程序流程。其 60 天不代表完整季节，更不代表实际园区分布。所有对外图表应注明“synthetic demonstration”。

转向真实系统后，至少应覆盖预期部署中的工作日 / 节假日、主要季节、典型负荷水平及设备可用状态。样本量是否足够应根据覆盖程度、学习曲线和独立验证判断，而不是仅看天数。

## 5. 常见口径错误

| 错误 | 后果 | 修正 |
|---|---|---|
| 基础电负荷中已经包含热泵和制冷机耗电 | 电负荷被重复计入 | 剥离已单独建模设备的耗电 |
| 将电表 kWh 当作 kW | 时长变化后费用失真 | 按采样间隔换算平均功率 |
| 天然气 m³ 与 kWh 混用 | 效率和成本量纲错误 | 明确热值口径并转换 |
| 用已限发的新能源实测值当可用出力 | 低估弃能且误判消纳率 | 使用可用功率估计或单独记录限发 |
| 直接改变为 15 分钟数据 | 回合、爬坡和能量更新不一致 | 同时修改模型、数据检查和观测编码；v0.1 会拒绝 |
| 日末重置储能，却不计日末偏差 | 人为获得免费能量 | 统一期末能量条件或采用跨日连续运行 |
