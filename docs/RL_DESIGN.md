# 强化学习建模与训练规则

## 1. 算法选择

| 算法 | 全称 | 在项目中的角色 |
|---|---|---|
| PPO | Proximal Policy Optimization，近端策略优化 | 首个连续动作基线；采用当前策略采样并分批更新 |
| SAC | Soft Actor-Critic，软演员—评论家 | 利用经验回放训练连续动作策略，作为第二个基线 |

本项目使用 Stable-Baselines3（SB3），不重新手写 PPO/SAC。这样工程师首先能集中检查能源模型、动作和评价口径。两种算法都支持本项目的连续 Box 动作；具体参数接口参考 [PPO 文档](https://stable-baselines3.readthedocs.io/en/v2.7.0/modules/ppo.html)和 [SAC 文档](https://stable-baselines3.readthedocs.io/en/v2.7.0/modules/sac.html)。选用版本为 SB3 2.7.0、Gymnasium 1.2.0，并非声明它们是最新版本。

## 2. 观测：13 维

代码中的顺序属于模型接口的一部分，训练完成后不能随意调整。

| 索引 | 特征 | 输入处理 |
|---|---|---|
| 0–1 | 小时正弦、余弦编码 | $\sin(2\pi t/24),\cos(2\pi t/24)$ |
| 2 | 剩余时段比例 | $(24-t)/24$ |
| 3–5 | 当前电、热、冷负荷 | 各除以 1000 kW |
| 6–7 | 光伏、风电可用出力 | 各除以 1000 kW |
| 8–9 | 购电、售电价格 | 以 CNY/kWh 的数值直接输入 |
| 10–11 | 电池 SOC、蓄热 SOC | 能量 / 容量 |
| 12 | 上一时段 CHP 燃气输入 | 除以 CHP 最大燃气输入 |

前一时刻 CHP 输入必须进入观测，因为它决定当前爬坡可行范围；SOC 决定储能可执行动作；剩余时段决定期末能量恢复的紧迫程度。

当前使用固定工程尺度，没有在全量数据上拟合均值或方差，因此不存在全量统计量引入测试信息的问题。输入不会强行裁成 [-1,1]；超出额定量级的真实数据应触发数据审查，而不是被悄悄截断。配置和观测定义变化后需重新训练。

**马尔可夫性边界：** 仿真器保存完整内部状态，但当前观测不包含天气过程等全部隐变量，所以对真实随机负荷和新能源过程只能视为观测驱动的 MDP 近似，不能声称严格满足马尔可夫性。需要时加入过去若干时段、可获得的预测量或循环网络，并单独验证。

## 3. 动作：5 维

策略输出 $a_t\in[-1,1]^5$：

| 索引 | 动作含义 | 物理映射 | 环境后续处理 |
|---|---|---|---|
| 0 | CHP 燃气输入 | $(a_0+1)\overline F^{chp}/2$ | 功率上限和爬坡限幅 |
| 1 | 热泵耗电 | $(a_1+1)\overline P^{hp}/2$ | 固定 COP 换算供热 |
| 2 | 电池母线功率 | $a_2\overline u^b$ | 基于 SOC 与效率限制；正放负充 |
| 3 | 蓄热母线功率 | $a_3\overline u^{th}$ | 基于能量与效率限制；正放负充 |
| 4 | AC 耗热 | $(a_4+1)\overline Q^{ac}/2$ | 不超过冷需求对应的耗热 |

**全零动作不是设备全关。** 第 0、1、4 维取 -1 才对应零出力；第 2、3 维取 0 才对应储能待机。

环境同时记录 `action_raw_i`、`action_executed_i` 和 `action_correction_l1`。校正后的功率影响物理转移及奖励；PPO/SAC 学习时仍使用策略自身输出及相应概率，不把修正后的动作反填入策略概率公式。

这里的 `action_raw_i` 指进入环境时的动作。SB3 内部可能已按 Box 范围处理策略输出，因此它不是 PPO 未裁剪的高斯潜在样本；本项目保留 SB3 原有的轨迹和概率处理逻辑。

这里采用的是分设备解析限幅和确定性补足规则，不是求解整个多能系统可行域的优化投影层，也不是可微安全层。

## 4. 奖励与约束怎样区分

奖励为运行费用、弃能惩罚、供能缺口惩罚和最后一步储能偏差惩罚之和的负值，详见 [数学模型](MODEL.md)。配置初值是调试起点，不能把惩罚系数大小等同于约束保证。

| 条件 | 实现方式 | 是否硬满足 |
|---|---|---|
| 动作上下界 | 映射与裁剪 | 是，针对声明的设备设定范围 |
| CHP 爬坡 | 依赖上一时刻出力的限幅 | 是，针对该简化 CHP 模型 |
| 储能功率与 SOC | 先限制可充放功率，再更新能量 | 是，针对该储能模型 |
| 电热冷供能可行性 | 补足设备 + 显式虚拟缺口 + 惩罚 | 否，需检查缺口指标 |
| 期末储能恢复 | 最后一步偏差惩罚 | 否，需报告期末偏差 |
| 电压、线路容量、水温、气压 | 未建模 | 无保证 |

调试时分开画各费用与惩罚项。如果智能体反复越过局部边界，应检查动作尺度、探索强度和可行域设计；如果在大惩罚下仍有缺口，先排查系统容量或模型是否根本不可行。

## 5. 回合与信息时序

每天 24 步是模型定义的有限运行周期，最后一步包含期末目标，因此返回 `terminated=True`、`truncated=False`。观测包含剩余时间，结束状态不携带下一天真实数据。

如果后续改为跨日连续运行，不能直接沿用本回合定义：应衔接储能、CHP 出力等状态，重新定义目标和终止语义。外部训练时间上限导致的中断才属于另一类截断。接口区别参考 [Gymnasium 时间边界说明](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/)。

示例假设在决策时能获取本时段有效负荷和新能源输入，属于理想化的小时级仿真。实际系统若只能在时段结束后知道小时平均值，必须使用时段开始可获得的预测或实时量测决定动作，再用实际值结算，不能直接照搬示例信息假设。

## 6. 训练默认值

| 参数 | PPO | SAC |
|---|---|---|
| 策略网络 | MLP，隐藏层 [64,64] | MLP，隐藏层 [64,64] |
| 学习率 / 折扣因子 | 3e-4 / 1.0 | 3e-4 / 1.0 |
| 每轮采样 / 批大小 | 1024 / 64 | 每步 / 128 |
| 其余参数 | n_epochs=10，GAE=0.95，clip=0.2，target_kl=0.03 | 回放池 100000，预热 1024，tau=0.005，自动熵系数 |
| 默认训练量 | 100000 环境步 | 100000 环境步 |
| 验证间隔 | 4096 环境步 | 4096 环境步 |

这些只是起始参数。需要在验证集上调整，禁止按测试集费用反复挑参数。不要用 PPO/SAC 的原始训练奖励直接互相比较，因为探索和熵机制不同；应加载确定性策略在同一测试集比较实际运行指标。

选模时完整遍历全部验证日，按“不可行小时数 → 缺口总量 → 平均总目标”的字典序保留更优模型。它优先排除不可行方案，但期末储能仍为软约束。若业务要求期末偏差不得超过阈值，应把该条件增加为选模可行性门槛。

## 7. 安全 RL 与多智能体的扩展位置

安全扩展可在 `core.py` 的动作执行前引入联合电热冷约束优化：尽量接近策略建议，同时满足可执行的设备和能量约束；不可行时返回明确故障并使用经过验证的备用调度。也可将缺口成本单独形成约束成本，用拉格朗日方法调整训练，但它依然不自动保证每步安全。

多个独立园区存在联络线、交易或隐私边界时，再考虑多智能体近端策略优化（Multi-Agent PPO，MAPPO）。届时需先确定各智能体的观测、共享约束和利益关系，再设计集中训练与分布执行。仅有多台设备并不必然要求多智能体。
